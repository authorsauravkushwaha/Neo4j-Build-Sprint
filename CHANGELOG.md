# Changelog

Two versions move independently: the **app** version (`package.json`) and the **dataset**
version (`neo4j/MANIFEST.json`). Every number below is reproducible with the commands in
`docs/verification.md`; nothing here is an estimate.

## Unreleased

- **Neo4j is now the primary graph database.** The Node backend (`server/`) connects
  to Neo4j using the official `neo4j-driver` over Bolt, executing the same
  parameterised Cypher catalogue the Deno/Edge-Functions path used. New REST
  endpoints: `/api/health`, `/api/health/neo4j` (real connectivity ping — fails
  honestly when credentials are missing), `/api/graph/stats`, `/api/query`
  (named-query dispatch only; arbitrary Cypher is rejected), `/api/graph/explore`,
  `/api/evidence/:id`, `/api/ledger/recent`. The in-memory read ledger records
  request id, query id, row count, execution time and a truthful `servedBy`
  label — error states are recorded as errors, not fabricated successes.
  Verification script: `npm run verify:neo4j` prints `PASS|BLOCKED|FAIL`
  verbatim. Legacy Postgres (PGlite) remains an opt-in fallback but is never
  labelled `neo4j-live`; without credentials the UI clearly shows DEMO DATA
  rather than silently falling back. Cypher catalogue reviewable in
  `neo4j/live-demo.cypher`.

- **Second-pass security audit: five defects found, demonstrated and fixed**
  (`docs/security-audit-round2-2026-10-16.md`, `tests/security/`, 57 adversarial assertions).
  Two of them were the first audit's own fixes surviving in a second copy of the same code —
  which is why both are now single-implementation.
  - The Edge Functions believed caller-supplied `cf-connecting-ip` / `x-real-ip` / the first
    `x-forwarded-for` hop, so one client could rotate its rate-limit bucket per request: 500
    requests produced 250 buckets, defeating the per-host ceiling on password guessing and the
    per-minute ceiling on the paid AI endpoint. Address selection is now explicit
    (`clientIpFromHeaders`, `TRUST_PROXY_HEADERS`, `TRUSTED_PROXY_HOPS`) and the same loop yields
    one bucket. `server/server.ts` already had this gate; the Edge path did not.
  - The browser carried a duplicate of the workflow HTTP probe that had drifted to
    `redirect: 'follow'` with credentials attached, so any allow-listed host with an open redirect
    was a trampoline to a host the policy refuses — with the learner's cookies. It now calls the
    shared hardened probe.
  - The browser signed a four-field canonical string against the server's five, omitting the
    nonce: enabling `REQUIRE_REQUEST_SIGNING` would have taken the AI and save endpoints offline
    rather than hardening them, and a captured request could have been replayed with fresh nonces.
    Both sides now share one canonical string, and the signer receives the nonce rather than
    inventing it.
  - Rate-limit bucket keys were an unkeyed hash under a constant published in this repository, so
    the table documented as holding "no personal data" could be swept offline back into email
    addresses and IPs. They are now an HMAC under `RATE_LIMIT_PEPPER`, and `/health-check` reports
    whether the pepper is set instead of implying a property it does not have.
  - `deploy.yml` interpolated `${{ }}` expressions straight into a `run:` block; both now arrive
    through `env:`, and a test fails on any expression reaching a shell in either workflow.
- **GitHub Pages deployment is now derived, not remembered.** The Pages workflow computes the
  base path and site URL from the repository (`/<repo>/` for a project site, `/` for a
  `<owner>.github.io` repository) instead of trusting a variable to be set, because the wrong
  base is the one deploy mistake that produces a blank page. A manual `workflow_dispatch` can
  publish any branch for review. The same rules live as pure functions in
  `scripts/pages-target.ts` with `tests/unit/github-pages.test.ts` covering each failure mode.
- **Deep links now work on GitHub Pages.** The build writes `404.html` from the built app
  shell (canonical link stripped, no inline script), so a shared link to
  `/careers/backend-engineer` renders the screen it names instead of GitHub's 404 page.
- The web-app manifest keeps `id` and its shortcuts inside the deployed path — without this
  the PWA will not install from a project site and its shortcuts 404 at the host root.
- `og:image` / `twitter:image` are advertised only when `public/social-card.png` has actually
  been rendered (`npm run emit:social-card`, now also run best-effort by the Pages workflow),
  and the card URL no longer doubles the base path (`/<repo>/<repo>/social-card.png`).
- `public/icons/*.png` are committed (generated by `scripts/generate-icons.py` from the same
  geometry as `favicon.svg`): the manifest has always promised them, and nothing in the build
  could render them, so every installable-PWA check was 404ing on all four.
- Account sync now also carries roadmap task progress (statuses, logged hours and notes), not just
  bookmarks, skill ratings and profile — stored in `public.user_task_progress` under the same
  role-scoped RLS as the other sync tables.
- The sync panel shows what your account currently holds before you download over a device.
- Progress page: a "This week" summary (tasks completed/touched and hours logged in the last
  7 days against your weekly target) and a downloadable Markdown progress report.

## 1.0.0 — 2026-10-14

First complete cut: a pre-seeded, account-free engineering career navigator that answers from
the browser without a network round trip, and optionally uses Supabase when configured.

**Dataset** — `datasetVersion 1.1.0`, seed checksum recorded in `neo4j/MANIFEST.json`:

- 16 engineering branches, 17 careers, 24 subjects, 37 concepts, 89 skills, 33 projects,
  154 resources, 13 learning modules, 16 self-check assessments, 37 tools and 8 languages.
- **444 nodes and 1,585 relationships**, emitted as 36 batched, MERGE-only Cypher statements.
- Every skill is reachable from at least two resources; every resource carries an access note,
  stated prerequisites, outcomes and limits, and a real time range (1–400 h, low ≤ high).
- 154 resource URLs are link-checked in `docs/resource-verification.md`; four providers reject
  automated checkers and are labelled as such in the app rather than quietly marked verified.
- Chemical/process, biomedical, industrial/manufacturing and surveying/geospatial slices were added on top of the
  original software/electronics/mechanical core; each slice passed the dataset gauntlet before
  the next was started.

**Product**

- Career explorer, skill-gap analysis against real prerequisites, dependency-aware roadmaps,
  project library with safety notes, resource library with access models, and a 3D knowledge
  graph view that is labelled as a visualisation of the shipped dataset, not live data.
- Guest mode works with no account; progress and preferences are local-only with reset,
  export and delete controls.

**Verification** — the state of the gates at this cut is recorded in `docs/verification.md`;
the honest summary is: unit/integration suite green, dataset self-check green, generated
Cypher in sync with the dataset, and every "verified" resource label produced by
`npm run verify:resources` rather than by hand.

**Known gaps** — listed in `docs/objections.md`, including the ones this repository cannot
close from inside the sandbox it was built in (no hosted instance, no Android APK artefact,
no third-party accessibility audit, no screen-reader user testing).
